# 共享聊天上下文摘要

SH-11，2026-10-26。共享版此前达到预算后只能新建会话；现在接入鸿蒙原有的上下文压缩流程。

## 来源与职责

- `ChatContextBudget.ets`直接复用锁定上游：字符数预算估算、按用户轮次拆分、覆盖点处理、
  增量历史、单一首条system消息、本地抽取以及固定压缩提示。
- `context-source.mjs`从同一版本的`pages/Index.ets`提取十个摘要/编排方法及返回契约。
  只替换配置、传输、取消与来源标记接口；缺少方法或替换锚点时立即失败，不修改参考输入。
- `adapters/platform/ChatContext.ets`连接当前保存的HTTPS服务、模型和凭据。
  摘要请求关闭思考、工具和响应正文日志，最大输出4096 tokens、读取超时120秒；响应文本限16000字符。
- `app/Index.ets`负责发送、附件、会话状态与原存储接口。没有新增Kotlin业务或第二套聊天数据库。

## 行为

短历史直接发送。达到估算阈值后，较早历史用当前配置模型压缩，默认保留最近8轮，设置可调整为2–20轮。
已有摘要按覆盖点复用；再次超预算时只摘要新增的较早历史，覆盖点不倒退。
若最近历史仍过长，原算法逐步缩减保留轮数并明确标记本地抽取；当前问题永远在最终请求末尾。
云摘要失败或为空时用原本地抽取算法，页面说明可能省略细节，不宣称是模型回复。

摘要不包含本轮问题、图片数据、历史图片路径、思考正文或只用于展示的工具轨迹。
从本地会话切换到云端会新建独立会话；摘要适配器也拒绝本地会话，避免隐式带入本地历史。
本轮图片在摘要准备后才接到最后一条user消息，并再次检查预算；超预算不会发送或丢弃历史。
首条拍照消息新建会话时保留待处理相机文件，避免创建会话的清理动作提前删掉附件。

原会话JSON继续保存`contextSummary`、`contextSummaryUpdatedAt`、
`contextSummaryUntilMessageId`和`contextSummaryMessageCount`。完整原始消息仍保留，
另插入来源提示；复用摘要不重复生成首次压缩提示。未知覆盖点明确报错，避免重新上传已覆盖原文。

停止、切换会话、摘要准备中切换主入口、页面隐藏、撤回授权或修改模型配置，都会阻止迟到摘要提交。
摘要和新消息在发送前通过原会话存储保存；写入异常时恢复内存中的摘要、消息与待发送输入，附件副本会清理。

## 验证范围与限制

```powershell
node shared-frontend/verify-context.mjs
```

检查真实生成的原编排代码与真实共享发送方法，覆盖摘要复用、增量覆盖、取消/撤回、配置变化、
错误/空响应本地回退、当前问题超预算、内存回滚、首条拍照附件、建会话失败重试与本地/云端历史隔离。
端口使用受控夹具，不表示真实模型质量。主机测试需使用Node24；构建脚本会在当前进程PATH中选择
锁定的Node20，连续运行时应另开shell或显式指定Node24执行上述测试。

设备专项`ChatContextDeviceTest`从实际聊天页输入合成问题，使用保留的`.invalid`域名触发网络失败，
验证本地抽取、完整历史、保存的覆盖点与Activity重建后的复用。测试只使用合成聊天和空凭据，
原偏好与会话索引在应用私有缓存内备份并在finally恢复，测试会话删除；不复制另一个应用的数据。
该专项需从独立、已force-stop的共享进程运行，避免前一个测试留下的原生偏好缓存影响夹具初始化。

预算沿用原默认256000与保留输出32768的字符粗估，并不代表具体模型的真实token窗口。
真实服务摘要质量、厂商差异、TalkBack、极端磁盘故障/进程中断和跨会话文件/索引事务仍需专项验收。
当前存储沿用原写入实现；内存回滚测试不构成断电安全或磁盘事务保证。
设备自动化使用实际渲染文字定位控件，不能据此宣称无障碍节点刷新问题已解决。
