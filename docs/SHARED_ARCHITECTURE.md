# ClawMate 共享前端与 Android 架构

主界面与可跨平台业务以锁定的鸿蒙 ArkTS 源码为准。Android 系统能力由 Kotlin 实现，
通过窄接口提供给共享前端；原 Compose 应用保留为回归基线。

## 工程归属

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| `shared-frontend/` | 上游版本锁、共享页面与业务、Android 平台接口、应用组装 | 只读上游输入；不复制 Kotlin 实现 |
| `shared-app/` | ArkUI-X Android 生命周期、权限、桥接和打包 | `:android-capabilities`、锁定 ArkUI-X 运行库 |
| `android-capabilities/` | 两版共用 OCR/ASR/TTS、图片准备、有界工作流执行及受限协议 | Android SDK、ML Kit、协程/JSON/HTTP；不依赖任一应用或 UI |
| `app/` | Compose 基线、其现存数据与尚未抽取的 Android 实现 | `:android-capabilities`；不依赖共享宿主 |

所有 Android 模块由根 `settings.gradle.kts` 管理。共享版不再维护第二套 Gradle 工程入口。
原能力的兼容包名暂时保留，避免无关的调用点重命名；同一能力只有一个实际引擎。

## 业务与数据归属

| 范围 | 共享版负责实现 | Compose 基线处理 |
| --- | --- | --- |
| 引导、导航、主题与页面 | 共享 ArkTS 页面；平台差异集中在适配层 | 保留，作为迁移前行为的参照 |
| 聊天与流式请求 | 原始 ArkTS 协议/会话 JSON；只读 query_events、有界工具往返、图片确认和取消 | 旧 Room 数据不被共享版自动读取或修改；图片准备引擎共用 |
| 图库与画像 | ArkTS 管线、索引、云协议及本地文件 | 旧图库 Room 数据保留；OCR 引擎共用 |
| 图库可恢复批次 | ArkTS保存用户选中图片的私有快照及原scan-session回执；Kotlin提供图片准备、内容摘要和窗口状态 | 原图库存储不自动迁入，共用私有路径校验和OCR实现 |
| 工作流 | ArkTS 编辑/保存/索引，桥接共用有界 Kotlin 执行器；由 ArkTS 写真实结果与日志 | 使用同一模型/解析/执行器；保留自己的存储入口，GUI/VLM受限 |
| 配置与授权 | 共享包私有偏好、独立声明版本 | 原 DataStore 保留；不隐式继承授权或密钥 |
| OCR、ASR、TTS | 调用共用 Kotlin 引擎；真实结果与权限/错误状态 | 调用同一库，保留自己的业务结果适配 |
| 采集提醒 | 原ArkTS面板/策略与前台确认；Kotlin独占提醒偏好、系统闹钟/通知及领取收据 | 不注册共享版提醒，不增加基线宿主通知权限 |

同一应用内每类数据只有一个写入者。桥接只返回能力结果，不写入另一套图库、会话或配置。
共享前端负责把结果纳入自己的状态与存储，因此无需把旧 Room 和 ArkTS JSON 同时写两遍。

两个包仍分别为 `com.clawmate.app` 和 `com.clawmate.shared`。这是保留现有数据的迁移边界；
统一构建与原生实现不等于已经切换正式包名。生产切换时应另做有版本的导入/校验与回退，
不能把修改包名当作数据迁移。

## 平台接口约束

- 共享接口不携带手机厂商品牌分支；具体系统能力可以返回可用、初始化中、取消或失败。
- OCR 只接受本地图片，受限解码并在后台执行；空文本与失败分别返回，不替换为示例文本。
- TTS 以真实引擎初始化及回调驱动界面；切换会话、离开前台与销毁时停止并清理资源。
- 耗时接口必须可取消、限制并发并丢弃过期结果，不能阻塞 Android UI 线程。
- 键盘可用窗口由 Android `adjustResize` 统一管理；共享入口关闭 ArkUI 的二次避让，
  组件不再额外平移输入区。键盘高度观测仍用于收起悬浮导航和滚动跟随。
- ArkTS 与 Kotlin 间传递有版本的 JSON 结果，不传任意类实例，不通过桥接执行任意命令。

## 后续抽取边界

图片附件/相机与ASR已桥接；真实云视觉、相机实拍和真人识别质量仍需验收。
每日采集提醒已接入共用Kotlin引擎；GUI执行器与本地推理继续按具体能力迁移。
共享业务已具备的云客户端、推荐、索引与工作流解析不重新包装为一套 Kotlin 业务。
鸿蒙 HDS 材质无法直接使用时，Android 适配保留几何、颜色、图标、交互与安全区；
不把基础模糊宣称为鸿蒙系统材质。

## 验证

先运行共用能力单元检查、两版构建与 Compose 回归，再运行共享 ArkTS 编译、契约与真机检查。
精确命令、失败和结果统一写入[迁移日志](../MIGRATION_STATUS.md)；不以工程依赖声明代替运行证据。

记忆同步页在确认目标模型与近7天范围后才启动原数据管线，使用单一同步门控。
取消会结束正在等待的非流式请求，并在模型输出提交前再次检查；成功批次的检查点保留。
共享工作流不给原生执行器文件目录，原生只返回结果；由 ArkTS 写入 `run_summary.json`
和成功 summary 日志。旧版的可选原生文件写入器继续只服务旧宿主，跨包不双写。
共享相机内容提供器只临时授权自己的相机缓存文件，不公开应用文件树。

聊天上下文继续复用原`ChatContextBudget`和锁定`Index`中的十个压缩编排方法，生成到
`platform/UpstreamChatContext.ets`；`ChatContext`只提供已保存模型配置、可取消传输和提交门控。
原会话结构的四个`contextSummary*`字段保存摘要与覆盖点，完整消息不被截断或双写。
当前问题及图片不进入历史摘要，图片只在准备完成后附加到最后一条请求；本地抽取与模型摘要分开标注。
详细范围见[上下文移植](CHAT_CONTEXT_MIGRATION.md)。

提醒接口返回v1 JSON和原生状态版本，ArkTS只持有界面缓存。通知PendingIntent直接进入Activity，
接收器不执行任务；宿主验证已发出的token/到期时间、前台及解锁状态，用户确认后先持久化当日领取收据，
再启动原任务页的有界批量。只有ArkTS成功保存非空summary日志才通知原生更新时间。
范围与时序限制见[采集提醒移植](COLLECTION_REMINDERS.md)。

工作流`vlm_qa`通过可选`WorkflowModelTool`进入每次运行的邮箱，ArkTS在逐次确认后复用
原云客户端和Decider设置处理图片；Kotlin等待有界回复，超时、取消或结束后拒绝迟到回复。
模型原文只作为步骤数据，ArkTS单独标记模型来源并独占写入运行结果与成功摘要。
Compose不注入模型端口；原GUI/HDC节点仍受限。兼容边界见[视觉问答移植](WORKFLOW_VLM_MIGRATION.md)。

图库恢复继续使用原分析器及队列。结果先落盘，单项回执后原子提交；进程退出后的遗留运行态
显示为暂停，用户确认后只派发未完成项，成功缓存可覆盖结果/回执之间的中断窗口。
Kotlin只校验私有副本内容并返回能力结果，图库记录/进度仍由ArkTS独占写入。
范围与保留策略见[图库恢复说明](GALLERY_SCAN_RECOVERY.md)。
