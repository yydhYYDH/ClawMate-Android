# 图库批次暂停与恢复

复用锁定鸿蒙版本`cd69b68bf16b9ed352be5073939eb24d042de583`的`GalleryPage`、
`GalleryAnalyzer`、`GalleryWorkQueue`和`GalleryScanSession`契约。
`shared-frontend/gallery-source.mjs`集中保存命中校验的适配，原参考树保持只读。

## Android流程

“选择图片”和“新建批次”进入系统选图器，每批最多9张。
界面先说明将保存去元数据JPEG私有副本：原始拍摄时间和位置不保留，日期记为导入日。
相同副本按SHA256去重；副本位于共享包`gallery-log/android-images/`，重启后不依赖临时相册授权。
复制后、继续分析前均通过原生层校验私有路径、大小与内容摘要；缺失或损坏不会伪装成成功。
显式重新选择同一图片可用正确内容原子修复其副本。

开始或继续时确认图库模型地址、模型名、剩余图片数量和可选远程向量服务。
继续会再次核对当前配置和隐私授权，不自动恢复上传。
已有未完成批次或损坏的进度需先确认替换；选择取消会保留旧进度和图库结果。
媒体副本在新进度提交前就已落盘，因此异常退出可能留下未引用副本；目前保留到用户显式清空图库分析。

## 状态和写入顺序

沿用`scan-session.json`以及`queued/done/skipped/failed`单项回执。
`processed`只计done/skipped，失败项仍属于未完成范围，点击继续后允许重试。
总数、已完成、跳过和失败数量始终从单项回执重算，不信任旧累计字段。
旧版“已有缓存”的skipped会归一为done，避免重复计为关键词跳过。

实际图片结果先经原`GalleryImageStore/GalleryStorage`保存，再提交相应进度回执。
若进程恰在两步之间退出，原分析器会复用已经成功保存的缓存；失败缓存仍重试。
进度文件限制大小、校验结构/身份/日期，写入同目录临时文件、检查写入长度后原子替换。
读取损坏会明确报错，不当成空进度或扫描完成；已有分析结果保留。
该方法未认证掉电持久性，也不保证网络请求恰好一次。

暂停停止新任务派发，已经进入OCR/模型流水线的图片允许完成并保存。
离开图库页、窗口失去前台解锁状态、撤回授权或修改配置时请求暂停。
确认过的在途图片仍可能完成；隐私撤回继续由原云客户端立即取消请求。
进程重启时将遗留running/pausing归一为paused，只有用户确认后才继续。
同进程跨页面的图片导入和分析共用执行门控，防止未提交副本被另一批次使用后又被清理；
旧队列或导入未结束前，另一页面不能清空图库目录。
Android可能冻结后台进程，在途工作不保证在后台完成；遗留状态在下次恢复时保持可继续。

## 范围

本项支持用户选择图片的可恢复批次；全相册后台枚举、PC/HDC批量读图和跨应用GUI采集仍受限。
不申请全图库或媒体位置权限，不使用伪造的模型回答。
真实视觉模型效果、完整私人图库选择、多厂商、省电杀进程、掉电与介质损坏仍需专项验收。
原始照片不受“清空分析”影响；该操作删除的是共享包内的结果、进度和私有图片副本。

精确命令、真实结果、早期失败和证据哈希统一记录于`shared-frontend/verification-gallery-scan.json`。
